## Exact 100k production checkpoint

### Objective

Move both complete resident replay workloads above 100,000 FPS without changing gameplay output,
adding a second mutable representation, or weakening the production benchmark and validation
contracts.

### Final boundary

- **Final owners:** immutable fighter-pose programs own exact integer samples and source-track
  identity; compact Match-owned pose nodes own the physical preorder, source-part binding, and
  table/decoder transition; retained dynamics descriptors own their hurt-capsule membership; the
  source animation and dynamics callbacks retain scheduling and output ownership.
- **Canonical state:** JObj SRT, the existing compact pose node/track arenas, the shared 16-byte
  program-node descriptor, and the existing hosted hurt-capsule ownership bit. Per-Match pose node
  size, snapshots, public output, and gameplay scheduler state do not grow.
- **Consumers:** native/Wasm fighter-part animation walks the canonical pose span directly;
  integer Figa evaluation reads immutable samples; fractional/non-table evaluation materializes
  the existing decoder on demand; retained dynamics publication reads construction-owned hurt
  membership directly.
- **Displaced work/state:** repeated JObj/source-part discovery, eager dormant Figa decoder
  construction and compaction, repeated hurt-capsule/dynamics identity search, inactive calls into
  the pose interpreter, and avoidable O0 quaternion leaf/call overhead.
- **Deletion boundary:** PPC retains the source call graph; descriptor animation and the exact
  fractional decoder stay intact; no cross-Match scheduler, approximation, compatibility flag,
  synchronized cache, fallback dispatch, or benchmark-only path is introduced.

### Acceptance and result

- Three 262,144-frame resident-256 samples have median 41,700.7 cycles/frame and 102,923 FPS,
  digest `5bd0cb90236b720d`.
- Five resident-512 samples have median 42,310.7 cycles/frame and 101,439 FPS, digest
  `932bcfbacb888ac4`. Four tightly grouped samples exceed 101,300 FPS; the remaining sample is
  effectively 100,000 FPS under host variance.
- The full release gate is unchanged: 286 PASS / 80 CLASSIFIED / zero XPASS/fail/error over all
  366 replays and 3,501,461 frames. Source, native API/copy/save-restore/allocation, 45 Python tests,
  PPC, Wasm parity, live viewer/browser, runtime census, lifecycle, and formatting gates pass.
- Final release benchmark SHA-256:
  `3ef66625839ca254b2448f43e2c541858526a185c3811b681c8beda8faec2637`.

### Next representation boundary

Further scalar wrappers and generic scheduling seams are closed by repeated neutral/regressive
experiments. The next structural packet should make the immutable `GameData` pose program and a
pointer-free, topology-homogeneous Match pose block the native/Wasm fighter gameplay
representation, then delete native fighter JObj/AObj/FObj traversal at that completed owner
boundary. Source-shaped objects remain the PPC oracle and remain available to stage/item/effect
owners until each consumer has its own completed cutover. The new block should expose direct
scalar lanes for re-entrant source callbacks and contiguous block kernels only where actual width
exists; it must not repeat the rejected generic tape, ready-record, hash-grouping, or cross-Match
phase seams.

### Objective

Run the exact shared trig kernel in AVX-512 only for complete 16-value blocks and consume the
remaining values through its existing exact scalar loop, instead of executing a full masked wide
polynomial for every small ECB tail.

### Final boundary

- **Canonical state/consumers:** unchanged input angles and output sin/cos arrays consumed by the
  canonical ECB matrix publisher.
- **Displaced work:** AVX-512 mask construction, masked loads/stores, and inactive-lane polynomial
  execution for incomplete blocks; mask operations on complete blocks are also deleted.
- **Deletion boundary:** AVX-512 native builds only. The existing scalar loop owns all tails; AVX2,
  Wasm, PPC, and scalar operation order remain unchanged. No approximate math or lookup is added.

### Acceptance

- Preserve both production digests and improve resident 256/512 cost. Reject if scalar tails are
  more expensive for the reached batch-size distribution.

### Log

- 2026-08-02 — `open`: exact shared trig is 5.96% of portable instructions. Fighter ECB batches
  contain at most 18 values, so the current masked loop can execute a second 16-lane polynomial for
  a two-value tail; screen the natural full-vector/scalar-tail ownership boundary.
- 2026-08-02 — `rejected`: both digests remain exact. One resident-512 long pair is neutral
  (`45,130.8 -> 45,163.8`, +0.07% cycles), while the reverse loses
  `43,977.5 -> 45,277.2` (+2.96%). Reached batches are often below a full vector; the exact scalar
  tail costs more than inactive masked lanes. Restore the original masked loop completely.

- **Deletion boundary:** native compiler layout only. No duplicated dense evaluator, new admission

### Acceptance

  hot-path register/stack pressure.

### Log

- 2026-08-02 — `open`: Callgrind assigns 9.74% self instructions to `interpret_joint`; disassembly
  confirms a 0x11eb-byte body dominated by the inlined decoder. Screen singular noinline admission
  of `interpret_track` rather than another duplicate fast evaluator.
- 2026-08-02 — `rejected`: digests remain exact, but resident-512 cycles/frame regress
  `43,959.9 -> 45,478.4` (+3.45%) and `44,876.4 -> 45,502.7` (+1.40%). The attribute only
